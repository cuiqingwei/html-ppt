01
概述与架构
理解本方案的核心原理与适用场景
第一章

方案概述

让 Claude Code 运行在本地，通过 Tailscale 隧道操作远程主机

本地机器 (运行 Claude Code)
└─ SSH MCP Server
└─ Tailscale 加密隧道
├─ 远程主机 web (100.x.x.1)
└─ 远程主机 dev (100.x.x.3)
💡 核心优势
  • 代码和数据存在远程服务器
  • 同时管理多台服务器
  • 无需在每台服务器安装 Claude Code
  • 跨网络访问内网服务器
📋 前置条件
  • 本地：macOS/Linux + Node.js 16+
  • 远程：Linux + SSH 服务
  • 订阅：Pro/Max/Team/Enterprise
适用场景

代码和数据存在远程服务器，本地只做开发；需要同时管理多台服务器（开发/测试/生产）；跨网络访问内网服务器（无固定 IP、无端口转发）

02
Tailscale 配置
基于 WireGuard 的 mesh VPN，无需端口转发或固定 IP
第二章

安装与配置 Tailscale

在所有设备上安装 Tailscale，组成私有网络

远程主机安装

Ubuntu / Debian 
curl -fsSL https://tailscale.com/install.sh |                    sh
sudo tailscale up
# 安装后会输出授权 URL，在浏览器中打开完成登录

本地机器安装

macOS
前往 tailscale.com/download 下载安装，使用同一账号登录
Linux
执行同样的安装脚本

验证连通性

验证命令 
tailscale status
# 输出示例：
100.89.10.1 web-server yourname@ linux active
100.89.10.3 dev-server yourname@ linux active
100.120.25.92 my-macbook yourname@ macOS -
tailscale ping web-server
💡 提示

Tailscale 个人版免费，支持最多 3 台设备；团队版支持更多设备

03
SSH 服务配置
配置免密登录，确保 MCP Server 能稳定连接
第三章

配置远程主机 SSH

确认服务运行 + 配置免密登录

确认 SSH 服务已启动

远程主机 
sudo systemctl enable ssh
sudo systemctl start ssh
sudo systemctl status ssh

配置免密登录（SSH 密钥）

本地机器 
# 生成密钥（如果还没有）
ssh-keygen -t ed25519 -C "claude-code-remote"
# 将公钥复制到各台远程主机
ssh-copy-id -i ~/.ssh/id_ed25519.pub ubuntu@100.89.10.1 # web
ssh-copy-id -i ~/.ssh/id_ed25519.pub dev@100.89.10.3 # dev

验证免密连接

ssh ubuntu@100.89.10.1
# 应直接登入，无需密码

本地机器上安装 mcp-ssh-manager
第四章

安装 SSH MCP Server

在本地机器上安装 mcp-ssh-manager

使用 npm 全局安装 mcp-ssh-manager

05
多主机配置
TOML 文件管理多台服务器，支持跳板机场景
第五章

方式 A：环境变量配置

适合 1~3 台服务器

编辑 ~/.claude/mcp.json：

mcp.json 
{
  "mcpServers": {
    "ssh-manager": {
      "command": "npx",
      "args": ["mcp-ssh-manager"],
      "env": {
        "SSH_SERVER_WEB_HOST": "100.89.10.1",
        "SSH_SERVER_WEB_USER": "ubuntu",
        "SSH_SERVER_WEB_KEYPATH": "~/.ssh/id_ed25519",

        "SSH_SERVER_DEV_HOST": "100.89.10.3",
        "SSH_SERVER_DEV_USER": "dev",
        "SSH_SERVER_DEV_KEYPATH": "~/.ssh/id_ed25519"
      }
    }
  }
}
⚠️ 命名规则

服务器名只能使用字母、数字和下划线，例如 WEB、DB_PRIMARY、STAGING。不能使用连字符（-）

第五章

方式 B：TOML 配置文件

推荐方式，适合 3 台以上服务器

步骤 1：创建配置文件

~/.ssh-manager/config.toml 
[servers.web]
host = "100.89.10.1"
user = "ubuntu"
private_key_path = "~/.ssh/id_ed25519"

[servers.db]
host = "100.89.10.2"
user = "admin"
private_key_path = "~/.ssh/id_ed25519"

[servers.dev]
host = "100.89.10.3"
user = "dev"
private_key_path = "~/.ssh/id_ed25519"
port = 2222

步骤 2：编辑 mcp.json

~/.claude/mcp.json 
{
  "mcpServers": {
    "ssh-manager": {
      "command": "npx",
      "args": ["mcp-ssh-manager"],
      "env": {
        "SSH_SERVER_WEB_HOST": "100.89.10.1",
        "SSH_SERVER_WEB_USER": "ubuntu",
        "SSH_SERVER_WEB_KEYPATH": "~/.ssh/id_ed25519",

        "SSH_SERVER_DEV_HOST": "100.89.10.3",
        "SSH_SERVER_DEV_USER": "dev",
        "SSH_SERVER_DEV_KEYPATH": "~/.ssh/id_ed25519"
      }
    }
  }
}
✅ 优点

新增或修改服务器只需编辑 TOML 文件，无需重新修改 MCP 配置，也无需重启 Claude Code

第五章

跳板机（Bastion Host）场景

通过跳板机访问内网服务器

跳板机 
# 跳板机配置
[servers.bastion]
host = "100.89.10.1"
user = "jumpuser"
private_key_path = "~/.ssh/id_ed25519"
内网服务器 
# 通过跳板机访问内网
[servers.internal_db]
host = "192.168.1.10"
user = "admin"
proxyjump = "bastion"
[servers.internal_cache]
host = "192.168.1.20"
user = "redis"
proxyjump = "bastion"
ℹ️ 工作原理

设置 proxyjump = "bastion" 后，连接内网服务器时会自动通过跳板机转发

07
常见问题
连接失败、MCP Server 未加载等问题的排查方法
第七章

常见问题排查

遇到问题时按以下步骤检查

连接失败

# 1. 确认 Tailscale 在线
tailscale status
# 2. 测试 SSH 直连
ssh -i ~/.ssh/id_ed25519 ubuntu@100.89.10.1
# 3. 检查远程主机 SSH 服务
sudo systemctl status ssh

MCP Server 未加载

# 检查配置文件路径是否正确
cat ~/.claude/mcp.json
# 检查 TOML 文件语法
cat ~/.ssh-manager/config.toml
# 重新启动 Claude Code

服务器名含连字符报错

⚠️ 命名规则

服务器名不支持连字符，需改为下划线：

❌ SSH_SERVER_WEB-SERVER_HOST

✅ SSH_SERVER_WEB_SERVER_HOST → 对话时说"web server"或"web_server"

补充内容
